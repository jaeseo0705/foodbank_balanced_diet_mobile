# Foodbank Balanced Diet Mobile

React Native + Expo 기반의 푸드뱅크 업무 시연용 모바일 앱입니다.

## 현재 화면

- 로그인 버튼을 누르면 인증 없이 **업무 선택** 화면으로 이동합니다.
- 업무는 **영양성분 등록 / 재고 현황 / 배분 추천 / 영양 계산** 순서로 가로형 카드 4개를 세로 배치합니다. 아이콘은 왼쪽, 업무명은 오른쪽에 두고 카드 안에서 세로 중앙에 맞춥니다.
- 프로필 버튼에서 설정, 앱 정보, 로그아웃으로 이동합니다.
- **영양성분 등록** 화면에는 영양성분표 그림과 **영양성분표 촬영 / 사진 불러오기 / 직접 입력** 버튼을 배치합니다. 촬영과 사진 불러오기는 시스템 카메라·사진 선택 화면으로 연결되며, 선택한 사진은 원본 비율로 미리보기합니다. 취소하면 기존 사진을 유지하고, 선택 해제로 초기 화면으로 돌아갈 수 있습니다. 사진을 선택한 뒤 **영양정보 읽기**를 누르면 iPhone의 Apple Vision으로 인식한 원문을 확인할 수 있습니다. 직접 입력·영양성분 항목별 자동 정리·영구 저장은 아직 연결하지 않았습니다.
- 나머지 업무와 설정은 제목과 뒤로 가기까지 연결된 기본 화면입니다. 재고 관리·추천·계산 기능은 아직 구현하지 않았습니다.
- 앱을 완전히 종료한 뒤 새로 실행하면 로그인 화면부터 시작합니다. 로그인 상태 유지 선택 여부와 관계없이 계정·로그인 상태를 저장하지 않습니다.
- 화면의 색상은 `src/theme.ts`, 업무 아이콘과 프로필은 `src/components/TaskIcons.tsx`에서 관리합니다.
- 상태 표시줄과 시각은 운영체제의 실제 표시를 사용합니다. 시안의 상태 표시줄을 이미지로 덧붙이지 않습니다.

## 맥북에서 iPhone 시뮬레이터로 실행

Xcode와 iOS 시뮬레이터, Node.js(22.13 이상, LTS 권장)가 필요합니다.

1. 터미널에서 이 프로젝트의 `package.json`이 있는 폴더로 이동합니다.
2. 처음 받았거나 의존성이 변경되었다면 `npm install`을 실행합니다.
3. `npm start`를 실행합니다.
4. **같은 터미널에서 Shift+i**를 누르고 **iPhone 18 Pro**를 선택합니다.

QR 코드는 실제 휴대전화의 Expo Go로 연결할 때 사용하는 것으로, 맥북의 시뮬레이터에서는 스캔하지 않습니다. 개발 서버가 실행 중인 터미널은 열어 둡니다. 종료하려면 Ctrl+C를 누릅니다.

### GitHub 업데이트 받기

- **git clone으로 받은 폴더**: 해당 프로젝트 폴더에서 `git pull`로 최신 코드를 받습니다.
- **Download ZIP으로 받은 폴더**: git으로 연결된 폴더가 아니므로 `git pull`은 작동하지 않습니다. 최신 ZIP을 내려받아 압축을 풀고 새 폴더에서 실행합니다.

## 검증

`npm run typecheck`, `npm test`, `npm run export`로 타입·화면 동작·iOS/Android/Web 번들을 확인합니다.
웹 브라우저 검사는 export 후 `npx playwright install chromium`, `npm run test:web`로 실행합니다(Python 3 필요).
GitHub Actions에서 같은 검사를 자동 실행하며 로그인·업무 선택 화면 캡처를 결과물에 보관합니다.

## 촬영·사진 불러오기

- 두 플랫폼에서 같은 `expo-image-picker` 코드를 사용하며 각 운영체제의 기본 촬영·사진 선택 화면을 엽니다.
- 촬영을 누를 때만 카메라 권한을 요청합니다. 사진은 시스템 선택기로 한 장을 선택하므로 전체 사진함 읽기 권한을 추가로 요청하지 않습니다.
- 권한 거부·선택 취소·오류를 처리하고 중복 실행을 막습니다. Android에서 카메라/선택 화면 실행 중 Activity가 재생성된 경우에는 등록 화면에서 미완료 결과를 복구합니다.
- 사진은 현재 등록 화면에서만 유지합니다. 서버 전송이나 사진함 저장은 수행하지 않습니다. iPhone에서 영양정보 읽기를 실행하면 사진을 기기 안에서 인식합니다.
- 업데이트 후 프로젝트 폴더에서 `npm install`을 실행하고 개발 서버를 재시작합니다. Expo Go에서는 이 모듈을 이용할 수 있습니다. 별도 개발 빌드를 사용하는 경우 새 네이티브 모듈과 권한 설정을 반영하려면 다시 빌드해야 합니다.
- **맥북의 iPhone 시뮬레이터에는 카메라가 없습니다.** 실제 촬영은 카메라가 있는 실기기에서 확인해야 합니다. 시뮬레이터에서는 맥북의 사진 파일을 실행 중인 시뮬레이터 화면에 드래그하여 사진 앱에 넣은 다음, 앱의 **사진 불러오기**로 선택할 수 있습니다.
- 자동 검사는 권한·취소·오류·중복 실행·사진 복구와 브라우저 파일 선택 흐름을 확인합니다. 실기기 카메라의 실제 동작을 대신 검증하는 것은 아닙니다.

## Apple Vision OCR 실행

- `modules/foodbank-vision-ocr`는 저장소 안의 작은 로컬 Expo 모듈입니다. 별도 OCR 모델이나 클라우드 API를 추가하지 않고 iOS Vision을 호출합니다.
- 한국어 우선·영문 병용·정확도 우선 모드로 처리하고, 글자·단위에 언어 교정을 적용하지 않은 원문을 반환합니다. 행별 위치(좌상단 기준 0~1)와 후보 신뢰도도 보존합니다. 이 신뢰도는 실제 정확도를 보장하는 수치가 아닙니다.
- 처리용 이미지만 EXIF 방향을 보정하고 긴 변 최대 3,200픽셀로 줄여 메모리 사용을 제한합니다. 원본 사진은 변경하지 않습니다.
- 사진 선택 → **영양정보 읽기** → 인식 원문 확인 순서입니다. 인식 내용은 현재 화면에서만 유지됩니다. 아직 영양성분 항목별 변환이나 자동 등록은 하지 않습니다.
- **현재 OCR은 iPhone/iOS 전용**입니다. Android와 웹은 사진 선택 기능을 유지하고 영양정보 읽기에서는 지원 안내를 표시합니다. 향후 Android OCR을 연결해도 같은 저장소와 공통 화면을 유지할 수 있습니다.
- **Expo Go에는 이 로컬 모듈이 없어 OCR이 동작하지 않습니다.** 기존 앱을 실행만 하지 말고 다음 순서로 네이티브 앱을 빌드·설치하세요.

```bash
npm install
npx expo prebuild --clean --platform ios
npx pod-install
npx expo run:ios --device
```

기기 목록에서는 **iPhone 18 Pro 시뮬레이터** 또는 연결한 **실제 아이폰**을 선택합니다. 첫 빌드에서 iOS 프로젝트가 생성되며 로컬 OCR 모듈도 함께 설치됩니다. 실제 아이폰 설치에는 Xcode의 Apple 계정·서명 설정이 필요합니다.

시뮬레이터에서도 **사진 불러오기 → 영양정보 읽기**는 시험할 수 있습니다. 실제 촬영은 카메라가 있는 아이폰에서 확인합니다. 이후 화면·JS만 바꿨을 때는 개발 서버를 다시 실행하면 되지만, Swift 코드나 로컬 모듈 설정을 바꾸면 다시 빌드해야 합니다.

### OCR 검증 범위

- 기존 자동 검사에 OCR 성공·빈 결과·실패·중복 실행·사진 교체/삭제 후 오래된 결과 무시와 네이티브 연결 오류 처리를 추가했습니다.
- Apple용 자동 연결에 `FoodbankVisionOCRModule`이 포함되는지 검사합니다.
- macOS CI에서 같은 Swift 인식 엔진을 컴파일하고 생성한 한국어/숫자 표본 이미지를 실제 Vision으로 읽습니다. 이어서 Expo 로컬 모듈까지 포함한 iOS 시뮬레이터 앱을 빌드합니다.
- 이는 실제 식품 포장 사진의 정확도 측정이나 실기기 촬영 검사를 대신하지 않습니다. 다양한 사진으로 별도 확인이 필요합니다.

## Xcode 27 / iOS 27에서 앱이 바로 종료되는 경우

`UIScene life cycle is required`는 카메라·OCR 권한 오류가 아니라, iOS 27 SDK가 요구하는 화면 생명주기가 생성되지 않았다는 뜻입니다. 현재 설정은 Expo SDK 57을 유지하면서 공식 `expo-build-properties`의 `ios.enableSceneSupport: true`를 적용합니다.

최신 코드를 받은 뒤 실행 중인 서버를 Ctrl+C로 종료하고 다음을 **한 줄씩** 실행하세요.

```bash
npm install
npx expo prebuild --clean --platform ios
npx pod-install
npx expo run:ios --device
```

`--clean`은 자동 생성된 **ios 폴더를 지우고 다시 만드는 명령**입니다. 화면 코드(`src`)와 OCR 원본(`modules`)은 그대로 유지됩니다. ios 폴더를 직접 편집한 경우에는 먼저 해당 변경을 백업해야 합니다. 기기 목록에서 **iPhone 18 Pro**를 선택합니다.

자동 검사는 생성된 Info.plist의 scene manifest와 AppDelegate 설정을 확인하고, 빌드 후 임시 시뮬레이터에 앱을 설치·실행해 시작 직후 종료되는 문제도 검사합니다. 검증에 사용한 Xcode/iOS 버전은 GitHub Actions 로그에서 확인할 수 있습니다.
